# 资料与工作目录

skill只包含工作流与排版预设。使用者提供自己的经历、目标JD、模板和可选照片；不附带任何个人示例履历，也不依赖预先存在的个人项目。

## 定位与初始化

优先使用用户明确指定的项目目录。否则在当前可写工作区创建独立目录，并在本次交付时说明位置。不要在skill安装目录保存个人资料；也不要读入与本任务无关的其他用户资料。

按实际需要建立以下文件，已有文件原地维护，不另建互相矛盾的事实副本：

| 位置 | 内容 |
| --- | --- |
| 项目状态.md | 当前目标、最新版本、缺失材料、下一步 |
| 资料库/经历库.md | 有稳定编号的事实与对应来源、贡献边界、时间及数字、后续更正 |
| 资料库/素材索引.md | 来源编号、原文件位置、存档位置及接收日期；必要时加文件哈希 |
| 资料库/已确认要求.md | 已确认偏好、适用范围、来源与替代关系 |
| 资料库/反馈与验证.md | 版本、反馈原意、修改动作、检查结果及未验证项 |
| 资料库/简历偏好.json | 当前用户的排版配置，可从skill的assets/resume-preferences.json复制后调整 |
| 素材/ | 用户提供的原件，模板、经历、照片分类保存 |
| 分析/ | JD映射、模板提取、内部页面图与版本检查记录 |
| 输出/ | 按用途、日期和版本保存最终文件 |

只有实际接收到信息才填入事实。不预填姓名、学校、公司、评分、证件、政治身份或联系方式。首次接收多份文件时可暂存待核实项，禁止将猜测补入已确认事实。

## 事实与版本

- 来源编号与经历编号分开，例如来源S001、经历E001；同一经历可有多次更新，不重复算为多段工作。
- 一条经历至少记录来源、时间或缺失状态、组织／项目、本人角色、行动及有证据的产出。原话、事实整理与某次简历改写分开保留。
- 日期冲突、停用要求和新数字用带日期的记录覆盖当前值，同时保留旧来源及历史文件。材料没有重复某经历，不自动等于删除。
- 课程、工具和证书按用户提供的实际名称选用；岗位要求不能反推用户已掌握。缺少项目开发时间时不拿数据覆盖区间冒充。
- 到岗时间、城市、每周天数等单次确认不自动适用于其他岗位。
- 保存需求和反馈的范围，用户只要求改一个符号时，不重做整份简历。已有事实更新不自动改写历次已投递版本。

## 新用户首次输入

确认目标岗位／用途和输出语言，接收经历及模板。没有模板时，可按用户授权选择简洁单栏样式；没有真实经历时先收集材料，不能把虚构示例作为个人简历交付。照片只在用户确实选择使用时接收。

## 迁移与共享

资料库与素材留在使用者自己的项目目录。迁移时保留目录内部相对关系，并让助手确认新目录；skill本身不写死用户目录。公开分享本skill时，仅打包skill目录及使用说明；个人项目和输出不自动随包分发。
