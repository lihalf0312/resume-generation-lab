# Private project configuration

This public edition has no fixed local paths or applicant data. Ask the user to identify an authorized private workspace and its authoritative templates/evidence before producing an actual applicant resume. Do not search unrelated machines or import the original author's records.

Keep private: project status, confirmed requirements, experience index and facts, optional supplied course inventory, template layout specification, material/source index, feedback/validation log, versions, job descriptions, photos and outputs. Resolve their actual filenames from user configuration; the names below are a suggested interface, not files bundled with this skill:

`project-status.md`, `confirmed-requirements.md`, `experience-index.md`, `experience-facts.md`, `courses.md`, `template-layout.md`, `material-index.md`, `feedback-and-validation.md`, `outputs/`.

Maintain one authoritative private fact store. A skill installation points to that store via user-local configuration rather than copying facts into public source. Migration requires explicit configuration of the new location, not a hard-coded developer username or drive path. Never publish local configuration, originals or outputs without separate authorization.
