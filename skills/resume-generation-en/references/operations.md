# Operation and review contract

Before any mkdir/write/input copy, configuration and preflight resolve the real installation and workdir paths and reject equality or containment in either direction, including symlink aliases. Separate unrelated directories are allowed. Direct preflight/render callers receive the same checks.

Keep one sequential task per workdir: input.json, immutable draft-first.json and analysis-first.json, versions/v00 onward, render-attempt receipts, content/changes/stage, PDF images, measurements and final delivery. `state.json` tracks progress; `status` resumes the same lineage without rereading unrelated sources. Never overwrite a previous version or first draft. Do not start multiple runtime commands concurrently on one workdir. For new source material or a later application, create a new workdir; existing delivery remains frozen. Record confirmed requirements, their scope, feedback and corrections beside task records rather than in the skill directory.

First render the unchanged first draft. Page overflow is a workflow state, not a reason to abandon or restart. Apply structure once: month abbreviations preserve precision; exactly matching award/end-month deduplication preserves the study range and award status; functional headings can fold into labels without dropping unique words; genuinely empty separators can disappear. These deterministic rules do not decide which experience is relevant. The optional pure helper `date_wrap_repair.repair(rows, measurement)` relocates an isolated `(awarded)` only when the measured last line proves that exact wrap; it preserves capitalization and date scope. It is not an automatic semantic quality decision and is not invoked by the CLI.

After structure, use up to four model-assisted semantic passes when needed. Merge duplicate meaning, compress secondary methods and omit weaker evidence while retaining important personal contribution, dates, units, conditions and status. Never use case-specific deletion rules. Keep before/after, reasons and exact source spans. At the bound preserve unresolved issues and editable files; do not mislabel an unverified draft as final.

Renderer invocation uses a unique profile, allowlisted environment, local working directory and no inherited credentials. An initial attempt plus at most two local recovery attempts is allowed per version. Save failure receipts; fix the concrete runtime fault and retry the same version. Do not kill another task's processes or relax source/network restrictions. If local execution approval is required, use the host's authorization process and preserve the incident/recovery record; this skill grants no bypass. Failed runs return nonzero. Only a hash- and identity-validated accepted-render receipt permits PDF reuse. A measurement file alone, failed post-measurement font validation, incomplete attempt or stale acceptance blocks structure, editing, freeze and cached reuse. Each attempt writes to a fresh render-attempt-NN directory, retaining obtainable artifacts, measurements, embedded-font program evidence and the actual exit/error result without overwriting prior attempts. Only successful measurement/token/style checks AND actual embedded-font verification create accepted-render.json. The receipt binds original DOCX/content/text, actual PDF and all evidence to the runtime/configuration/font/template/mechanics identities. Configuration correction can retry the same original DOCX only within the initial-plus-two total; legacy measurement is never silently accepted. A workdir cannot be used for concurrent tasks.

Inspect all actual page PNGs at sufficient scale and read extractable text. Measurements include page count, body geometry, paragraph physical lines, bottom space, style invariants, text mapping and last-line ratios. Headings, dates and one-line fields are exempt from prose tail targets. Multiline bullet tails under 50% are advisory; under 15% require visual/editorial attention, not filler. Sparse supported source may legitimately leave white space; do not invent content to fill the page. Mapping failure is a measurement failure, not a typographic defect. The preserved paragraph/word mapping supports same-content comparison but is not an ATS test.

Check body/heading fonts and embedded PDF font names, spacing, bullets, alignment, rules, dates, capitalization, repeated or missing words, extraction order, overflow/cropping and every link actually used. No supplied photo or hyperlinks are inserted by this minimal CLI. Declared actual contact text can be entered as a section item; automatic clickability and photo handling are outside this release.

Self-review JSON requires `images_inspected`, `source_review_completed`, `writing_review_completed`, and `remaining_issues`. Add specific image observations, source comparisons, unresolved questions, lower-density explanations and measured version reference. These booleans are editor declarations, not machine proof. Freeze verifies one page, exact style package invariants, content token mapping and body bounds, copies DOCX/PDF/text from that version and records hashes. It does not certify truth. Unresolved questions safely omitted may accompany a safe delivery; claims used despite unresolved necessary truth questions must block editorial acceptance.

Report actual OS, Python/dependency versions and renderer from preflight, not an assumed platform. The runtime is a POSIX/Linux reference implementation using fontconfig and LibreOffice. No native Windows/macOS installation, native Microsoft Word pagination, cross-engine rendering, real ATS ingestion, inaccessible URLs, or automated semantic truth is verified by this package. Rerender on the destination environment before use. The Python audit hook rejects network attempts made through Python; it is not OS isolation or a subprocess/network security sandbox. No provider SDK, model API, credential storage, ledger or external account is included.


For independent review, use [review/status records](review-status.md). Optional `observations` in self-review must be a list of objects with that declared schema; freeze validates their shape only. Preserve original reviews, normalization mappings, label/rationale conflicts and later corrections separately. Do not count schema passes, positive observations or advisory tail flags as factual acceptance. The supported/unsupported modes and baseline-to-product coverage are enumerated in [capability coverage](capability-coverage.md).

When natural source-supported wording permits, prefer multiline prose tails beyond half of the available paragraph width, ideally about two thirds to four fifths. These remain advisory preferences; preserve scoped user edits and never pad, shrink or rewrite unrelated material to satisfy a ratio.

Record feedback and confirmed requirements with scope (general, role family or this task), date/source and explicit replacement links where relevant. Unconfirmed improvements remain proposals, not universal preferences. New material does not automatically regenerate earlier delivered files.

RC3 source-linked entry date correction uses optional after_date on a replace operation, separately or alongside after text. It consumes an ordinary semantic pass and logs full row states; it does not infer dates or bypass exact-before/material-citation checks. Read source-and-writing.md for the field/type/row-kind rules. Generic tests exercise date-only and text-plus-date updates, stale-before and bad-citation rejection, wrong row/action/type rejection, and the corrected DOCX date field.

Freeze explicitly checks the current rendered-content lineage for delivery invariants: synthetic input has exactly the fixed marker, real input has no automatic marker, and the single Target line retains the intended role and exact Target: prefix. A semantic removal or mutation cannot be accepted merely because the page still fits. Guard results are saved in FREEZE.json separately from semantic-truth declarations.

RC4 incomplete recovery: `status` exposes the current `recovery.version`, actual `recovery.attempt_evidence` entries and accepted-render path or blocker. In each attempt inspect `result.json` for actual returncode/stdout/stderr or exception; missing final result after interruption is an incomplete attempt and still consumes its slot. Inspect images/measurement only in the receipt's accepted attempt for downstream decisions. Follow the reported version directory to editable resume.docx and content.json. Overflow can proceed through the one structure stage and remaining ordinary semantic passes, never a new limit. A rejected freeze leaves state.frozen false and no delivery; an exhausted fourth semantic pass with unresolved overflow remains incomplete. Preserve editable files, status, terminal rejection and remaining issues. Render exhaustion likewise stops after three attempts. Do not reset counters, create a replacement task for the same retry, bypass acceptance, change typography or call an unverified draft final. See [README recovery instructions](../README.md#rc4-acceptance-and-incomplete-recovery).
